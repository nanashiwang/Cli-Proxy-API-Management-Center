Use personal/main for pushes and Bun for existing application checks. New user-facing strings still require all supported locales. Backend and frontend release versions remain separate.

Before adding a feature, inspect adjacent flows and the current source of truth; shared filters, data definitions and access rules must not diverge across entry points.

Quota refresh controls display server-provided next-check deadlines and skip cooling accounts for both individual and batch actions. Management quota reads reuse the backend observation cache and Retry-After/backoff policy.

Background quota display consumes existing `codex_quota` / `provider_quota` snapshots in both quota card hosts, timeline and recovery sorting. Visible connected pages synchronize the local auth-files list every 15 seconds without provider calls. Per-window observation/reset times and guard health distinguish retained values from fresh verification; manual provider details remain separate.

Usage insights accept optional backend service-health counters and nullable rates. Service trends and dimension error rates exclude cancellation, caller errors and unknown records; incomplete delivery is a service error. Retained-record scope is explicit, legacy totals/billing and old-backend rendering remain intact. Backend sources and boundaries are recorded in CLIProxyAPI/docs/CODEX_PROXY_NOV17_CN.md.

OpenAI-compatible providers persist optional `test-model` through management GET/PUT/PATCH and YAML reload. Empty selects the first configured model; this preference does not change gateway routing. The management test selector supports case-insensitive model search. Other provider families retain their existing test-preference semantics.

OpenAI-compatible connectivity tests use `max_completion_tokens`, with one legacy `max_tokens` retry only for an explicit HTTP 400 unsupported-parameter response. The selected model and credential remain unchanged.

OpenAI-compatible providers and individual keys have persisted IDs. Rename, notes and reordering preserve account-pool membership; management mutations target provider ID with legacy fallback. Per-key notes appear in the editor, detail view and account groups. Legacy IDs are retained; only a unique matching historical pool binding is recovered. First load persists migrated IDs in the configuration. Ambiguous missing references remain inert.

Upstream integration uses v8 grouped providers under `/config/api-keys/:family`, credential operations under `/credentials`, and the shared model-rules workspace. Provider source positions and inherited runtime policies survive edits alongside personal IDs, key notes and test models. New routing, discovery, plugin, payload replacement and OAuth entry points reuse upstream implementations. The seven locales retain personal labels; new locales use English fallback for existing personal features.

Quota refresh keeps upstream raw response handling and personal next-check deadlines, isolated by connection generation. Bulk credential refresh uses the upstream result dialog. The quota guard remains in the advanced configuration section and persists top-level `quota-guard`; the removed legacy quota-switch controls are superseded by v8 routing.
The auth-file supported-model dialog edits per-file exclusions through field-only PATCH, with independent copy/search controls and save/discard handling. Candidates combine registered models with persisted exact exclusions so users can restore filtered models. Shared wildcard semantics and global OAuth locks remain distinct; wildcard rules are editable without inventing account support from the provider catalog. Runtime credentials remain read-only.

The usage page enables error-origin filtering when the v8 dashboard advertises support. The cost cell distinguishes Fast and Ultrafast using the request-time billing snapshot.
